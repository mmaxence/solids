# solids v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Orbits leave the universe and become layered Kepler rings in the scene gravity interaction; the landing shows what a new shape costs an agent; the side menu gets two tiers with collapsible groups.

**Architecture:** Three independent edits to existing files, each with its assertions added to the single check page (`scripts/check.mjs`) and the site generator (`scripts/gen-site.mjs`). No new files beyond this plan and its spec.

**Tech Stack:** TypeScript + esbuild, headless Chrome check (`npm run check`, needs the sandbox bypass), static site generator.

**Spec:** `docs/superpowers/specs/2026-10-30-solids-v5-design.md`

## Global Constraints

- Zero dependencies; full bundle stays about 20 KB gzipped (size budget enforced by the check).
- No em dashes in any copy or doc.
- Check page is one template literal: no backticks or `${` in case code; `[0-9]` instead of `\d`.
- Native over JS: the menu uses `<details>` with no script.

## Review Focus

1. A scene whose orbiters all sit at the same rest distance (the hero's ring at 27 vmin): rings must still spread (equal distances give equal rings; the clamp alone decides).
2. Switching the center when ring order changes: the 800 ms blend covers the new target; no NaN when the center and an orbiter overlap (rest distance 0).
3. Universe markup from v4 with `gravity="center"` on a child: it must behave like a free body, and Copy code must not reintroduce it.
4. Cost sentence when `dist/sizes.json` or an object folder is missing a README: the build must fail loudly, not print NaN.
5. Keyboard users on the menu: `<summary>` is focusable and toggles with Enter and Space natively; the current link stays reachable when its group is open.
