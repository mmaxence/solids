# solids v4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn `<sd-universe>` into a 3D cloud with a perspective camera (spin, drag, pointer tilt), unique per-body motion, 3D orbits, and optional collisions.

**Architecture:** `SdScene` gains a `step(dt)` hook (after object updates, before interactions) and sizes each quad from the object's scale (8 device-px steps, culled when off-canvas). `SdUniverse` keeps bodies in a unit ball, advances camera and bodies in `step`, and writes `anim.offset/scale/z`, `effectParams.defocus` and `anim.state` per frame. Children carry `data-pos` and are centered by a `::slotted` rule. The site, docs and checks follow.

**Tech Stack:** TypeScript, WebGL2, esbuild; checks via `scripts/check.mjs` in headless Chrome (`npm run check`, sandbox bypass needed).

**Spec:** `docs/superpowers/specs/2026-10-29-solids-v4-design.md`

## Global Constraints

- Zero dependencies; full bundle ≤ 60 KB, core ≤ 18 KB gzipped (check enforces).
- No em dashes anywhere in site copy, docs or code comments.
- Reduced motion: no autonomous motion; pointer-driven changes allowed.
- `npm run check` must print `ok` at the end of every task (run with the sandbox bypass).

## Review Focus

1. A universe resized after generation (band on window resize): rects re-measured, projection uses the new W/H, nothing drifts off center.
2. Drag on touch: `touch-action: pan-y`, pointercancel mid-drag releases cleanly (no stuck capture, inertia from last velocity).
3. `perspective` near 1 (D = 1.6): a body at z = 0.95 gets s ≈ 2.5; scale, quad and glow must not blow up or clip; `s` is clamped to [0.3, 3].
4. A pasted universe whose children have `data-pos` but whose `count` differs: children win, no regeneration, bodies from the children.
5. Context restore / `paused` toggling: the step hook does not accumulate dt while stopped (dt is capped at 100 ms by the loop already).
