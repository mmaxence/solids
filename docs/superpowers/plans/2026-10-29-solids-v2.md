# solids v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship solids v2: a full-viewport landing hero, Display P3 color, and a doubled catalogue (12 objects, 12 effects, 7 interactions).

**Architecture:** Three independent streams on three worktrees off `main`, merged B → C → A. Each stream extends `scripts/check.mjs` and must leave `npm run check` green on its own branch.

**Tech Stack:** unchanged (TypeScript, esbuild, WebGL2, custom elements, Node scripts, headless Chrome).

**Spec:** `docs/superpowers/specs/2026-10-29-solids-v2-design.md` (and v1 spec next to it).

## Global Constraints

- Zero runtime dependencies. Budgets: core ≤ 18 KB, full ≤ 60 KB gzipped (update `scripts/check.mjs` `sizes()`).
- Every new object/effect follows the v1 contract (`docs/SKILL.md`), with README, two or three uniforms, no em dashes.
- Reduced motion: no self-driven motion; pointer- and scroll-driven motion still responds.
- `npm run check` must print `ok` on each stream branch (run with the sandbox bypass locally).
- Commit per logical step on the stream branch; do not push.

## Review Focus

1. A `color` value the browser can't parse (`color="nope"`): keep the previous color, no console error. (B)
2. A scene with one object and `interaction="collide"`: no NaN, no movement. (C)
3. `scroll` interaction when the scene is taller than the viewport: progress clamps 0..1, no jump at the edges. (C)
4. Hero on a 500 px wide viewport: dock readable, no horizontal overflow, title not under the dock. (A)
5. P3 canvas on a browser without `drawingBufferColorSpace` (Firefox): colors parse in sRGB, nothing throws. (B)

### Task B: Display P3 color

**Files:**
- Modify: `src/core/gl.ts` (`createGL` sets `drawingBufferColorSpace`), `src/core/math.ts` (`parseColor`), `src/core/object.ts` (color attr uses the scene's space; re-parse on attach), `src/core/scene.ts` (`colorSpace` field), `scripts/check.mjs` (cases + budgets), `site/src/intro.md` ("Color" section), `docs/SKILL.md` (one paragraph), `scripts/gen-site.mjs` (COLORS palette → P3 strings), `src/objects/*/README.md` (snippets use P3 accents).

**Interfaces:**
- `createGL(canvas): { gl, colorSpace: 'display-p3' | 'srgb' } | null` (change the return shape; scene stores both).
- `parseColor(s: string, space: 'display-p3' | 'srgb' = 'srgb'): [r,g,b] | null`. Hex/rgb() fast path returns sRGB floats when `space === 'srgb'`; when `space === 'display-p3'` every input goes through the 2D-canvas path (`getImageData(0,0,1,1,{colorSpace:'display-p3'})`). Browser-parsed path uses a module-level 1×1 canvas and a `Map` cache keyed by `space + s`. Returns null when the browser rejects the string (`ctx.fillStyle` unchanged after assignment).
- Objects keep the raw `color` attribute string; `rgb` is recomputed from it on attach (space known) and on attribute change.
- P3 default palette (gen-site `COLORS`, hero, READMEs): `color(display-p3 0.55 0.85 1)`, `color(display-p3 0.78 0.66 1)`, `color(display-p3 1 0.55 0.8)`, `color(display-p3 0.5 1 0.85)`, `color(display-p3 1 0.8 0.5)`, `color(display-p3 0.55 1 0.6)`.

- [ ] **Step 1:** Add check cases (RED): `color="color(display-p3 1 0.2 0.2)"` → finite rgb; `color="oklch(70% 0.2 30)"` → finite rgb; `color="nope"` after `color="#ff0000"` → rgb stays red and no console error; on a scene whose `colorSpace === 'display-p3'`, `#ff3333` parses with r < 1 and `color(display-p3 1 0.2 0.2)` parses with r ≥ 0.99. Raise budgets to 18/60 KB. Run check: expect FAIL on the parse cases.
- [ ] **Step 2:** Implement `createGL`, `parseColor`, scene/object wiring.
- [ ] **Step 3:** Swap the palette and snippets to P3 strings; add the Color section to intro.md and a paragraph to SKILL.md.
- [ ] **Step 4:** `npm run build && npm run site && npm run check` → `ok`. Screenshot `objects/orb.html` to confirm the orb still renders.
- [ ] **Step 5:** Commit `feat: display-p3 color`.
